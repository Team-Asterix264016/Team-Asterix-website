# Do later — community, blog and newsletter

Deferred on 11 Oct 2026. Ordered by impact; each item says why it matters and what it needs.

## 1. Shareable post links and search visibility (highest impact)

**Why:** posts live at `/#community/blog/<slug>`. Search engines ignore everything after `#`, so no post can be indexed, and WhatsApp, LinkedIn and X show the generic site preview for every shared post.

**Needs:**
- Real paths such as `/community/blog/<slug>`. `vercel.json` already sends every path to `index.html`; the community page would read `location.pathname` instead of the hash, and old `#community/...` links should redirect.
- Per-post preview tags (`<title>`, description, `og:image`, canonical URL). Crawlers don't run JavaScript, so these have to be in the HTML the server returns: a Vercel function or an Express route that injects them into `index.html` for `/community/blog/*`.
- `sitemap.xml` and an RSS feed (for example `/api/blog/rss.xml`) generated from published posts.

## 2. Sending newsletters from the Mail Cluster

**Why:** the Mail Cluster can copy and export addresses but cannot send.

**Needs:**
- An email provider (Resend, Amazon SES or Cloudflare Email Service) and a sending domain with SPF, DKIM and DMARC.
- A compose screen with preview and a test send to yourself.
- The per-person unsubscribe link (already generated by the Mail Cluster) in every email, plus a `List-Unsubscribe` header.
- Batching within the provider's limits; bounces and spam complaints feed the opt-out list; a send log.
- **Before the first send:** set `UNSUBSCRIBE_SECRET` on Render so unsubscribe links keep working if `JWT_SECRET` ever changes.

## 3. Stronger bot protection on subscribe

Only if bot signups get past the hidden decoy field and the per-IP rate limit. Add Cloudflare Turnstile to both subscribe forms and verify the token on `POST /api/subscribers`.

## 4. Projects showcase

- A consent checkbox on the project submission form ("show my project publicly").
- An admin "feature" toggle on submissions.
- A public endpoint that returns only safe fields (title, summary, department, year), never email, phone or the Drive link.

## 5. Discussions

- Thread and reply models.
- Posting only for logged-in participants who have changed the default password, so nobody can post as someone else.
- Rate limits, a report button, and an admin moderation tab (hide, delete, lock).
- Show first name and department only.

## 6. Blog extras

- Scheduled publishing (publish at a set date and time).
- Image upload inside the post body (today the editor takes image URLs there; only the cover has an uploader).
- View counts and "more from this category".

## 7. Navigation label

The blog is now the main content of the Community page. Decide whether the navbar item should read "Blog" or "Community & Blog".
